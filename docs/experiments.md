# 实验设计与真实结果

## 实验范围

本项目把验证分为四层：真实模型问答、确定性故障与消融、纯图像模型接入、软件单元/集成测试。四层结果不能相互替代。所有业务材料都是虚构教学样例，公开记录没有课程报告的个人信息。

## 30题三组真实模型比较

三份3页文档：港湾借阅、果园库存、星图排班。每份10题，共12道文字事实题、6道表格题、6道跨段题、6道不可回答题。问题标签和期望证据由评测器读取，Actor/Reviewer 只收到问题、文档 ID 和工具，不能读取标签文件。

模型为 `deepseek-flash`，温度0，输出上限1800 token，角色工具交互最多8轮并有最终输出步骤；三组使用同一模型、提示词和输入。测试题各自使用空且冻结的记忆。应用层工具预算32用于两个受控网关组，基线没有该包装；本次无人触发预算。执行并发数为3，逐题轮换模式顺序。模型名称是供应商别名，未来映射可能变化；温度0也不保证完全确定。

| 题目数 | 30 | 30 | 30 |
| 核心答案规则通过 | 30 | 30 | 30 |
| 完成率 | 100% | 100% | 100% |

计时从 `WorkflowEngine.run` 开始到其结束，不包括 MCP 子进程启动/退出；并发和供应商响应波动都影响延迟。底层工具调用包含实际读取与证据检查，缓存命中不计，`tools/list` 不计。优化版比基线减少约32.3%的底层调用，但平均耗时增加约6.7%，不能称为总体加速。模型请求数接近，没有明显 token 节省。

全部规则通过说明小样本存在难度上限，没有提供准确率提升证据。30/30的 Wilson 95%区间为[88.65%,100%]，仅是该二项计数的描述；样本非随机、文档内题目相关，不能当总体性能置信保证。

### 规则分数与语义复查

`score_answer` 检查标签中的必需术语/数值与回答状态。它防止把12误匹配为112，也不会把执行失败算作成功拒答，但不能理解全部解释性句子的逻辑。

AI代理按原文进行90份最终回答的二次核查，发现3题6份回答有附加断言问题（基线2、工程版3、优化版1）：

| 问题 | 发现 | 含义 |
| --- | --- | --- |
| harbor-09，工程版 | 从设备预算推断“自建设备” | 预算项目不等于部署方式 |
| orchard-03，基线/工程版 | 由超过阈值必须复核，反推未超阈值无需复核 | 条件命题不能任意逆推 |
| atlas-10，全部三版 | 将未给出额外费用的具体答案，扩大为全文没有费用相关信息 | 原文其实提到不收报名费及不处理交通报销 |

未发现核心问题答案/拒答判定或引用身份错误；这不等价于全文完全正确。二次核查由AI代理完成，不是独立人类标注，也不把84/90另行命名为人工语义准确率。公开审查记录保留原回答和逐项说明，原始规则分数没有被改写。

## 故障注入与消融

11场景×5变体，共55次确定性运行，零模型 API 调用。场景包含正常执行、伪页码、跨文档引用、伪造引文、缺失引用、真实引文配错误结论、暂时超时、持续故障、未验证记忆、过期记忆和Reviewer写入污染经验。

这些脚本角色刻意服从注入的错误，用于测试软件守卫能否拦截；它们不代表真实模型发生错误的概率。

| 变体 | 正确且出处合法的作答 | 拒答 | 不安全作答 | 执行失败 | 记忆写入 |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 1 | 0 | 8 | 2 | 1 |
| engineered | 2 | 0 | 8 | 1 | 1 |
| optimized | 4 | 5 | 1 | 1 | 0 |
| optimized_no_gate | 3 | 0 | 7 | 1 | 1 |
| optimized_no_memory_filter | 2 | 5 | 3 | 1 | 0 |

每行合计11个结果。记忆写入是另外的行为计数。5次拒答发生在资料本身仍然可用、但脚本反复给出非法引用的场景，因此属于保守拒答，**不能当作答对**。持续工具故障造成失败也不计为安全作答。

`optimized_no_gate` 用允许通过的 gate 替换真实 gate，因此同时移除了该组件承担的历史引用重验，但保留可信标记筛选；`optimized_no_memory_filter` 取消读取时的可信标记筛选及历史重验，仍保留最终答案 gate。这里的消融边界按实际依赖关系定义，不能把共享机制当完全独立变量。

证据守卫减少了错误引用进入最终输出的机会，记忆过滤拦截了两种历史经验误导。全部变体仍会接受“引文2000人、结论9000人”这一反例，直接说明**来源正确不等于语义蕴含**。

## 纯图像对照

另设两幅条形图、三道题。文档JSON和图注没有目标数值，PDF仅嵌入栅格图像；答案标签与工具数据目录分离，代理不能读取。两组均使用优化工作流、单并发、空且冻结的记忆。

关闭 `DOCAGENT_VISION` 时三题均完成但拒答，规则通过0/3；开启后分别正确回答27、15和16，规则通过3/3。跨图题返回两幅图的引用。关闭/开启的模型请求总数分别为19/15，平均工作流耗时约7.91/6.01秒。

这证明三道示例中图像内容经MCP传入视觉模型产生了可观察效果，不构成普遍多模态能力或性能提升的统计结论。

## 工程验证

本地全量测试62项通过，Ruff检查通过。包含真实MCP子进程的版本协商、6工具、图像字节保真、错误后继续调用、越界路径拒绝、异步取消、预算、缓存去重、引用校验和评测器边界。

120页临时PDF集成测试验证导入、大纲、第7与113页证据检索，以及第120页图像传输。它不调用模型，因此只证明工程能力。Java监听示例使用JDK11.0.28编译运行，实际观测Actor与Reviewer在后台线程按依赖顺序执行并安全退出。

```powershell
python -m docagent faults --output-dir outputs/robustness
$env:DOCAGENT_VISION='0'
python -m docagent evaluate --data-dir examples/vision/documents --questions examples/vision/questions.json --modes optimized --concurrency 1 --output-dir outputs/vision_off
$env:DOCAGENT_VISION='1'
python -m docagent evaluate --data-dir examples/vision/documents --questions examples/vision/questions.json --modes optimized --concurrency 1 --output-dir outputs/vision_on
```

所有真实模型原始计数和逐题记录见 `results/`；运行时模型服务、网络和别名版本变化可能改变结果。
